# Wrapping Panier Recettes with Capacitor

The interface is a mobile-first web app. Native shells can load it later without rewriting screens.

## What is already in place

- Screens are responsive and sized for a phone column.
- The UI calls `/api/...` with relative URLs. There is no hardcoded host in client code.
- Auth is an HTTP cookie (`pr_session`). Locale is another cookie (`pr_locale`).
- `public/manifest.ts` is generated by Next as a web app manifest, and `public/sw.js` caches same-origin GET pages for offline reopening. API calls are not cached.
- Server rendering only loads data. Buttons, forms, and the language toggle run in the browser.

## Suggested later setup

1. Deploy the Next server (see the Dockerfile). Capacitor should point at that origin, or at a bundled static export only if you later split the API. Do not assume `localhost` inside a phone.
2. Add Capacitor beside this app, not inside `src/`:

```bash
npm install @capacitor/core @capacitor/cli @capacitor/ios @capacitor/android
npx cap init "Panier Recettes" ca.panierrecettes.app --web-dir .next
```

3. Prefer a remote server URL over shipping the Next server inside the WebView:

```ts
const config = {
  appId: "ca.panierrecettes.app",
  appName: "Panier Recettes",
  webDir: "public",
  server: { url: "https://your-host.example", cleartext: false },
};
```

4. Allow the session cookie on that host (`SameSite=Lax` already). Use HTTPS so `secure` cookies work in production.
5. `npx cap add ios` and `npx cap add android`, then open the native projects. Camera or file access for a future receipt photo can be a Capacitor plugin; the current receipt screen pastes text and needs nothing native.

## What not to do

- Do not call Node or Prisma from a screen component. Those imports stay in `src/app/api` and `src/lib` server modules.
- Do not special-case `window.location.origin` for API calls.
- A store scrape must keep running on the server. The phone should only ask `/api/prices/refresh`.
